## 1. Executive Summary & Core Philosophy

**TRUSTGUARD AI** is a radically honest, production-grade personal digital-safety web platform. In an era where cybersecurity vendors offer deceptive "100% safe" guarantees and consumer AI assistants harvest sensitive personal inputs, TrustGuard AI operates on three unbending pillars:

1. **Radical Honesty**: *"We do not know what we cannot verify, and we never treat unknown information as safe."*
2. **Absolute Transparency**: Every assessment is accompanied by a **Security Visibility Score**, an itemized breakdown of what was verified vs. unverified, and clear disclosures of browser sandbox blind spots.
3. **Zero Raw Sensitive Data Storage**: Sensitive user inputs (SSNs, API keys, passwords, bank numbers, credit cards) are stripped, redacted, or masked client-side before reaching server persistence.

TrustGuard AI is **decision-support software**, not antivirus, malware removal, or law enforcement. It provides structured, calm, actionable intelligence that empowers users to make informed security decisions.

## 2. The Radical Honesty Guard & Vocabulary

TrustGuard AI enforces an uncompromising safety vocabulary across all user-facing interfaces and backend reporting:

| Term | Meaning & Contract |
| :--- | :--- |
| `SAFE_LOOKING` | Checked signals matched known safe patterns. *Never claimed to be unconditionally safe.* |
| `LOW_RISK` | No critical threat signals found, but minor advisory warnings exist. |
| `CAUTION` | Suspicious signals, uncommon redirect chains, or missing essential headers detected. |
| `HIGH_RISK` | Active indicators of compromise, phishing heuristics, or brand impersonation found. |
| `CRITICAL_RISK`| Confirmed malicious indicators, verified malware/phishing list match, or private network exploit. |
| `UNKNOWN` | Information could not be retrieved, verified, or contacted. **Never converted to safe.** |
| `UNABLE_TO_VERIFY` | Target domain timed out, blocked connections, or refused inspection. |
| `NOT_CHECKED` | Feature or third-party reputation check is unconfigured or disabled by user preference. |
| `DEMO_DATA` | Synthetic fixture data shown for demonstration purposes. |

### The 9 Mandatory Report Elements
Every security evaluation generated by TrustGuard AI contains all 9 required elements:
1. **Target**: Canonical URL, domain, or snippet fingerprint analyzed.
2. **Assessment Status**: One of the strict status tokens above.
3. **Summary**: Plain-language executive finding.
4. **Verified Signals**: Exhaustive list of checks that succeeded with evidence.
5. **Unverified / Blind Spots**: Honest disclosure of what could not be inspected.
6. **Actionable Recommendations**: Clear, prioritized steps for the user.
7. **Security Visibility Percentage**: Ratio of verifiable signals to total ideal signals.
8. **Technical Details**: Expandable diagnostic accordion with raw headers, TLS issuer, IP classification, and timing.
9. **Mandatory Advisory**: Non-dismissible disclaimer stating this is decision-support, not an absolute guarantee.

## 4. Key Feature Matrix

| Pillar | Features | Description |
| :--- | :--- | :--- |
| **Website & Link Scanner** | DNS Pinning, TLS Inspection, Brand Lookalike, Header Scorer | Deep passive reconnaissance with SSRF protection preventing access to loopback, link-local, private, cloud metadata, and test networks. |
| **Privacy Check** | Luhn Card Check, SSN, API Keys, Passwords, One-Click Redact | Instantly highlights sensitive tokens before submission with a one-click "Protect My Data" button replacing them with safe placeholders. |
| **Trust Assistant** | Gemini Flash + Structured Schema + Deterministic Fallback | Generates 5-part structured guidance (Summary, Immediate Actions, Long-term Advice, What We Checked, What We Couldn't Check). |
| **Emergency Response** | 8 Deterministic Checklists (Compromised Account, Stolen Device, Phished, etc.) | High-speed, guaranteed-available checklists that operate offline with zero network or AI dependency. |
| **Sandbox Transparency** | Browser Capability Evaluator & Blind Spots Matrix | Real-time audit showing what web APIs can see vs. what they cannot see (running processes, installed apps, local disk). |
| **Data Control & Rights** | Instant Data Export, Account Deletion, Automated Retention | 100% GDPR/CCPA compliance with self-service 1-click JSON data export and permanent account scrubbing. |
| **Inclusive Design** | Dark, Light, High-Contrast, Colorblind (Prot/Deut/Trit), 4 Font Scales | Full WCAG 2.1 AA compliant UI, keyboard navigation, and screen reader announcements. |

## 5. Getting Started & Local Development

### Prerequisites
- **Node.js**: v20+ (v24.19.0 LTS recommended)
- **npm**: v10+ (v11.17.0 recommended)

### Installation
Clone the repository and install all workspace dependencies from the root directory:

```bash
git clone https://github.com/balukota9494-sudo/code-x.git
cd code-x
npm install
```

### Environment Configuration
The repository includes pre-configured environment templates. Ensure the following files exist:

#### Server (`server/.env`):
```ini
PORT=3001
NODE_ENV=development
SUPABASE_URL=https://rxyxenrcccxbshcnkygf.supabase.co
SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
GEMINI_API_KEY=AIzaSy...
GEMINI_MODEL=gemini-2.5-flash
USER_HASH_SALT=trustguard-user-hash-salt-prod-2026-v1
ALLOWED_ORIGIN=http://localhost:5173
```

#### Client (`client/.env`):
```ini
VITE_SUPABASE_URL=https://rxyxenrcccxbshcnkygf.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
VITE_API_BASE_URL=http://localhost:3001
```

### Running the Application

#### Start Backend Server:
```bash
npm run dev --workspace=server
# Running on http://localhost:3001 (Health check: http://localhost:3001/api/v1/health)
```

#### Start Frontend Client:
```bash
npm run dev --workspace=client
# Running on http://localhost:5173
```

#### Run All Services Concurrently:
```bash
npm run dev
```
